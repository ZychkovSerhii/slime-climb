## Перемалювати спрайт у коді

Відкрий `sprites/<key>.js`. Кадр — це масив рядків однакової довжини. Кожен символ означає колір із `palette` спрайта, а `.` — прозорість. Одна клітинка дорівнює `cell` пікселів (зазвичай 4).

- Сітка мусить влазити в полотно `w × h`. Якщо вона менша, її буде вирівняно по центру.
- **Не міняй `w` і `h`:** від них залежать хітбокси, а отже баланс.
- Анімація — це список назв кадрів і `fps`. Назви анімацій, які викликає код (`idle`, `jump`, `run`, `bite`, `fly`, `shoot`, `crawl`, `legs`), мусять лишитися.
- `outline(rows)` з `grid.js` автоматично додає темний контур.
- `npm test` ловить помилки: нерівні рядки, колір без палітри, сітку, що не влазить, анімацію з неіснуючим кадром.

## Замінити готовим малюнком (Aseprite, Piskel тощо)

1. Намалюй кадри одного спрайта в один рядок, зліва направо. Порядок кадрів — як у `frames` у файлі спрайта. Розмір кожного кадру — рівно `w × h` зі спрайта.
2. Збережи як `png/<key>.png`, наприклад `png/bat.png`: два кадри по 40×28, тобто файл 80×28.
3. Перезбери гру (`npm run build`). Збірка сама знайде файл, правити код не треба.

Якщо розмір файлу не збігається, гра попередить у консолі й візьме намальований кодом спрайт, тож гра не зламається.

Фон замінюється файлом `png/bg.png` (зима — `png/bgWinter.png`, бамбук — `png/bgBamboo.png`, туман — прозорий `png/fog.png`) будь-якого розміру. Він тайлиться, тому краї мають стикуватися.

- Етап 6c: скін `slimeShkodko` («Я ШКОДЬКО», той самий розмір, що `slime`) і `sack` («Мішок Шкодька», кадри `sack`/`shake`) — `sprites/<key>.js`.
