# Етап 12 — онлайн-таблиця лідерів (дизайн)

Дата: 2026-11-12. Статус: затверджено користувачем у чаті.

## Навіщо
Змагатися з друзями за висоту. До релізу гру мають лише друзі; **перед релізом дані таблиці стирають** (рішення користувача).

## Цілі
- Спільна таблиця: топ-50 за висотою і власне місце гравця.
- Зараховуються лише забіги на наборі «Норма» без змін (усі множники `Tuning` = 1, `heal: 'game'`) і без дебаг-параметрів URL (`?kazan=1`, `?loop=N`, `?weapon=…`, `?cards=…` тощо).
- Нік вводить гравець, фільтр мату на клієнті й на сервері.
- Гра працює без інтернету: результат стає в чергу й відправляється пізніше.

## Не цілі
- Групи / коди друзів (варіант Б відкинуто).
- Сильний захист від накрутки (Play Integrity, підпис забігу).
- Адмінка: записи видаляють у консолі D1 на сайті Cloudflare.
- Акаунти, вхід через Google.

## Анти-цілі (провал, навіть якщо працює)
- Гра гальмує чи падає без мережі або коли сервер недоступний / вичерпав безкоштовний ліміт.
- Нік чи результат відправляються без відома гравця (нік — лише після явного введення).
- Записи з «Легко», «Важко», власних множників чи дебаг-старту потрапляють у таблицю.

## Обмеження
- Cloudflare Workers + D1, безкоштовний план (5 млн зчитувань рядків і 100 тис. записів на день; понад ліміт запити падають до 00:00 UTC, гроші не списуються).
- Акаунт Cloudflare і API-токен створює користувач; Claude паролі й токени не вводить. Токен — у секретах GitHub (`CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`), розгортання з CI.
- Google Play: форма Data safety (нік, результат, випадковий ID пристрою) і політика конфіденційності — до релізу.
- Логіка клієнта — чисті функції в `src/systems/` з тестами (як решта проєкту).

## Підходи
- **А. Одна спільна таблиця** — найпростіше; після релізу туди прийдуть усі.
- **Б. Групи за кодом** — таблиця лишається «для своїх» і після релізу; ~удвічі більше роботи й ще один екран.
- **В. А + запасне поле групи** — без глухого кута, але робота наперед.
- **Обрано: А.** Користувач: «перед релізом просто зітремо дані». Запасне поле групи й версію балансу прибрано. Свідомо прийнятий ризик: після релізу таблиця публічна зі слабким захистом, накрутку прибирають вручну.

## Рішення (затверджені користувачем)
- **Сервер:** один Worker, одна таблиця D1. `POST /score` — надіслати результат; `GET /top?id=…` — топ-50 і місце гравця.
- **Ідентичність:** випадковий ID пристрою (створюється при першому запуску, у `localStorage`). У таблиці — **лише найкращий результат кожного гравця**.
- **Нік:** 3–16 символів; питаємо при першому відкритті таблиці або першій відправці; змінити — у меню. Однакові ніки дозволені.
- **Що рахується:** лише висота (`heightPoints(distancePx)`, без очок за вбивства), лише «Норма» без дебагу. Інакше результат не надсилається і на екрані кінця забігу видно «Не Норма — у таблицю не йде».
- **Захист:** перевірка правдоподібності висоти щодо тривалості забігу + ліміт частоти запитів з одного ID. Видалення — консоль D1.
- **Без мережі:** черга в `localStorage`, повтор пізніше; таймаут запиту, жодних блокувань гри.
- **Екрани:** кнопка «Лідери» в меню; після забігу — «Твоє місце: N» (або стан «надсилається / офлайн»).
- **Розгортання:** користувач створює акаунт і токен, кладе в секрети GitHub; Claude дає покрокову інструкцію; Worker розгортається з CI.

## Залишено будівельнику (рішення Claude, можна переглянути)
- Структура: `server/` у тому ж репозиторії (Worker + `schema.sql` + `wrangler.toml`), свої тести. Клієнт: `src/systems/Leaderboard.js` (правила зарахування, черга, валідація ніка), `src/systems/Profanity.js` (спільний з сервером словник), сцена `LeaderboardScene`, введення ніка — HTML-поле поверх канви (як шар довідника), бо Phaser не має нормального текстового вводу на Android.
- Правдоподібність: висота ≤ (інтеграл максимальної швидкості прокрутки за `timeSec`) / `pxPerPoint` × запас; формулу виводимо з `BALANCE` (`scrollBase`, `scrollGrowth`, `maxScrollSpeed`) і перевіряємо на бот-забігах, щоб чесні забіги не відкидались. Також `timeSec` у розумних межах (напр. ≤ 3 год).
- Ліміт частоти: не частіше ніж раз на 20 с з одного ID (зберігається в D1 разом із записом).
- Фільтр мату: нормалізація (нижній регістр, латиниця-двійники → кирилиця, `0→о`, `@→а`, прибрати повтори й розділювачі) + корені укр/рос/англ лайки. Відомо, що щось пропустить.
- Дозволені символи ніка: кирилиця, латиниця, цифри, пробіл, `_ - .`; без емодзі.
- CORS: дозволити `https://localhost` / `capacitor://localhost` (Capacitor) і `http://localhost:*` (розробка).
- Адреса Worker'а — у `src/config/leaderboard.js`; поки не розгорнуто, кнопка «Лідери» показує «Таблиця ще не підключена».
- Схема: `scores(id TEXT PRIMARY KEY, nick TEXT, height INT, time_sec INT, updated_at INT)`, індекс за `height DESC`.
- Стирання перед релізом: команда `DELETE FROM scores` у консолі D1 — записати в CLAUDE.md.

## Як зроблено (2026-11-12)
- **Шар «Лідери» — HTML** (`src/leaderboard/`), а не сцена `LeaderboardScene`: там і поле ніка, «Назад» закриває його (`backAction(…, leaderboardOpen)`).
- **Дебаг = будь-який параметр URL** (`isEligibleRun`), а не перелік ключів.
- **Правдоподібність — точний інтеграл** `min(scrollBase + scrollGrowth·t, maxScrollSpeed)` / `pxPerPoint` + 2 (висота в грі — накопичена прокрутка, боси її лише сповільнюють). Чесний забіг не відкидається; узгоджена підробка висоти й часу проходить.
- **Окремий `POST /nick`** і **окремі ліміти** 20 с для результату (`last_submit_at`) і ніка (`nick_at`): у браузерній перевірці спільний ліміт відкидав результат, якщо нік зберегли менш ніж за 20 с до смерті.
- **Екран кінця забігу:** «час · висота», рядок статусу (`statusLine`); без ніка рядок «Введи нік — тапни тут» відкриває «Лідери» з курсором у полі, після закриття результат надсилається, місце показується.
- **D1** створено через Cloudflare MCP (EEUR), схема застосована; upsert перевірено на справжньому D1. Worker не розгорнуто — потрібні кроки користувача (`docs/leaderboard-setup.md`).
- **Після рецензії:** (1) відправка на екрані кінця — один запит у польоті (`data.lb.inFlight`), відповіді малюють через поточний `this.lbShow` і лише для свого забігу (клавіатура на Android перебудовує екран — перевірено зміною розміру вікна); (2) короткі корені мату (`еба`, `сука`, `dick`…) — лише на початку слова: «Себастьян», «Кебаб», «Асука», «Сучков» проходять, «Dickson», «Ebay» — ні (відома хиба); (3) 429 → статус `later` («Надішлемо трохи згодом»), а не «Офлайн».
- **Свідомо не зроблено:** ліміт за IP. Ліміт за ID обходиться новим ID на кожен запит, а `timeSec` до 3 год дозволяє висоту ~554 тис. Для таблиці друзів прийнято; перед публічним релізом — ліміт за `CF-Connecting-IP` і стеля `timeSec` за реальними забігами.
